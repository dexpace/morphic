## Findings

### issue: the cycle scan no longer sees `#name` edges, but the resolver follows some of them, so an anchor-based pure-$ref cycle kills the process with a fatal stack overflow. One shape the scan refused before this commit now crashes.
`compilers/openapi/internal/nodeview/nodeview.go:430` · rule: CLAUDE.md "Sweep every site of the mechanism before closing it"; catalog `justification-must-be-load-bearing`, `differential-against-the-library`. The scan package doc says what the scan is for: "A reference cycle that never reaches a concrete schema recurses without bound inside the resolver".

The new refusal is justified by the claim that the resolver "never walks one as a pointer … `#name` is a $anchor it looks up by name if at all", and that walking it refused "a cycle the resolver never enters". The same commit's new `resolve.go` comment says the library *does* resolve such fragments when the reference sits inside the schema that declares the anchor. I confirmed that. Taken together, every `#name` edge is now invisible to the scan, including the ones the resolver follows.

I built `cmd/morphic` at HEAD and at BASE (3515599f^) and ran `morphic compile <spec> -skip-validate` with a 20–30 s timeout:

| spec | BASE | HEAD |
|---|---|---|
| `A: {$anchor: a, $ref: '#a'}` | exit 2, `fatal error: stack overflow` in `oas3.(*JSONSchema).resolve` (resolution.go:168) | same crash |
| `A: {$anchor: a, properties: {n: {$anchor: b, $ref: '#a'}}, $ref: '#b'}` | crash | crash |
| the #523 repro plus one line, `$anchor: x-s` on `A` (root `x-s: {$ref: '#x-s'}`, `A: {$anchor: x-s, $ref: '#x-s'}`) | exit 1, `error openapi/cyclic-ref 9:7: cyclic $ref: reference chain never reaches a node without a $ref` | **exit 2, `fatal error: stack overflow`** |
| `A: {$anchor: a, properties: {next: {$ref: '#a'}}}` (no pure cycle) | — | exit 1, morphic's own `unresolved $ref "#a"` and no library error, so the library resolved `#a` |
| `A: {$anchor: a, $ref: '#b'}`, `B: {$anchor: b, $ref: '#a'}` | — | library refuses: `jsonpointer must start with /: b` |

What this costs:
- The plain anchor self-cycle already crashed at BASE. The scan never modelled anchors; before this commit it only walked the name as a root key by accident.
- The third row is a real regression: a document the compiler used to refuse with a diagnostic now ends the process.
- A Go stack overflow cannot be recovered, so `recoverCycleScan`, the engine and the harness's no-panic oracle all die with it.

I found no tracker issue for anchor-driven `$ref` cycles. I searched `anchor cycle`, `stack overflow`, `$anchor` and `cycle scan`, each with `created:<2026-09-26`. #12 and #26 are the closed pointer and alias forms of this same crash class.

Fix: do not drop the edge. Give the scan the resolver's anchor lookup. For a `#name` fragment, find the schema declaring `$anchor: name` in the same schema resource (the scope the library's registry resolves within, per the rows above) and follow it as a hop. Where that lookup is ambiguous, refuse conservatively. Add the three crashing specs above as `scan` fixtures and put one under `testdata/` for the harness sweep. If this is deferred, the nodeview comment must stop calling non-pointer fragments safe to ignore, it must name the limitation at the site, and it must be filed.

### nit: the `TestDetectCycles_AnchorFragmentIsNotWalked` doc comment gives each case the other case's job
`compilers/openapi/internal/scan/scan_internal_test.go` (new test) · rule: catalog `assertions-claim-what-name-says` / CLAUDE.md "a doc comment that is imprecise".

The comment says the pointer-spelled twin "fails if the leading-'/' refusal is reverted (which would also swallow this real cycle)". I ran two mutations of `nodeview.go:430` against `go test ./compilers/openapi/internal/scan -run TestDetectCycles_AnchorFragmentIsNotWalked -v`:
- **Revert to `if false {`:** the anchor case FAILs and the pointer twin PASSes. The revert does not swallow the real cycle.
- **Refuse the key, `if strings.Contains(pointer, "x-s") {`:** the anchor case PASSes and the pointer twin FAILs.

So the twin catches the key-refusing fix and the anchor case catches the revert. The comment states the opposite. Fix: swap the two clauses and drop the parenthetical.
