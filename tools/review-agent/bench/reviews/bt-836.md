### nit: findCommand's doc says the not-found path happens only when cobra finds no command, but help and completion take it too
`cmd/morphic/dashes.go:51-53` · rule: catalog `contract-covers-every-outcome` / `universal-claims-check-every-site`; CLAUDE.md "a doc comment that is imprecise"
The doc says findCommand returns false "when cobra finds none. Cobra reports that itself when it runs". The probe below built `./cmd/morphic` at HEAD:
```
morphic help -version            → morphic: unknown shorthand flag: 'v' in -version          (exit 2)
morphic help compile -opt=a=1    → morphic: unknown shorthand flag: 'o' in -opt=a=1         (exit 2)
morphic completion bash -version → morphic: unknown shorthand flag: 'v' in -version          (exit 2)
morphic bogus -version           → morphic: unknown command "bogus" for "morphic"            (exit 2)
```
`help` and `completion` join the tree only as cobra executes, so at this point `root.Find` returns an error for them and `found` is false. Cobra then finds and runs those commands, and it reports no "not found". What it does report is pflag's shorthand misreading. singleDashLongFlags' own doc already states the exception ("help and completion join the tree only as it executes"), so the new helper's doc contradicts the doc of its only caller. The same rationale is now written three times within 35 lines: in the caller's doc ("A command not found here is cobra's to resolve"), in the inline comment at line 25, and in findCommand's doc. Catalog `single-source-no-restated-copies` and `reread-final-prose` ask for one statement.
Fix: say what the bool actually means, that `root.Find` resolved args without error, which is false for an unknown command and for help/completion. Keep the rationale in one place, the caller's doc, and remove it from the other two.

### question: should `any(e).(type)` be the accepted spelling of a deliberate errorlint exception?
`compilers/openapi/internal/load/load.go:984-991` · rule: `.golangci.yml` nolintlint rationale ("a suppression outliving what it suppressed is invisible without this"; `allow-unused: false`, `require-explanation: true`)

I could not search the tracker for a recorded decision on this (blind-review scope). If the trade is intended, the commit body is the place to say so.
