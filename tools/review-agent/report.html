Morphic Reviewer

A review agent for morphic, built from what Omar's own reviews caught after a PR was pushed. It checks a change against CLAUDE.md, the Go styleguide and 130 rules learned from the PR history, and it proves each finding by running something.

What you have

Everything lives in tools/review-agent/. Two files do the work; install.sh copies them into ~/.claude, because .gitignore keeps .claude/ out of the repository.

The agent

morphic-reviewer.md

The reviewer itself. It says how to review: what to run, in what order, what counts as evidence, and how to write the report. Runs on Opus.

The catalog

catalog.md

The reviewer's rulebook: 130 kinds of mistakes, each with a real example from the PR history and the check that catches it. The agent reads it at the start of every review.

The build and the bench

build/ · bench/

The scripts and data that generate the catalog, and the back-test briefs, ground truth, reviews and grades. The README says how to rerun each.

How it was made

  1. Collected Omar's PRs. 228 in dexpace/morphic and 16 in dexpace/styleguide, with every commit, review comment and PR body. Most of the signal was in the 788 commits pushed after a PR's first commit, because each one fixes something a local review found and explains why.
  2. Held back 20 PRs so the finished reviewer could be tested on PRs it had never learned from.
  3. Extracted the lessons. Haiku agents read the other 224 PRs and wrote down each defect a fix commit or review comment caught, with an exact quote. A script checked every quote against the source and kept 890 verified findings.
  4. Grouped them into rules. Findings that describe the same mistake were merged into one rule. The result is 130 rules in 12 review passes. Every count in the catalog is computed from the findings, not typed by hand.
  5. Wrote the agent around three passes: run the gate, check the written rules no tool enforces, then apply the catalog.
  6. Back-tested it blind. The agent reviewed six held-out PRs as they were at their first commit, with no access to what came later. A separate grader then compared its report to the fixes the PR actually made.

How a review runs

Pass 0 · The gateRuns make gate exactly as CI does: lint, the 100% coverage gate, archtest and the rest. It reports the result rather than re-checking those rules by eye.
Pass 1 · Written rulesChecks the CLAUDE.md and styleguide rules no tool enforces: title length with the (#NNN) suffix, limits stated in code, decisions already recorded on the tracker, omitempty versus omitzero, bounded recursion.
Pass 2 · The catalogApplies the 12 passes. It proves findings by compiling the specs a comment talks about, planting mutations, diffing two declaration orders and sweeping every site of a mechanism.

The report goes to ~/.cache/morphic-review/<label>.md in Omar's format. Each finding starts with issue:, question:, suggestion: or nit:, shows the command it ran and what came back, and is followed by a list of what was probed and came back clean. The agent works in its own worktree. It never pushes, never posts to GitHub and never edits your checkout.

What it missed, and what changed

Most misses came from checking a comment's claim only in the case its author measured. v2 tells the agent to test each claim in the opposite case (cold cache instead of warm, N elements instead of one, a non-zero index), to mutate each part of a built pointer separately, to check that every failure path reports the same way its siblings do, and to treat a defect the change makes worse as part of the change.

How much to trust these numbers

  • Six PRs is a small sample. One PR can move recall by ten points.
  • Recall for v2 has not been measured yet. The two PRs it reviewed had no fixes to their first commit to compare against. The next benchmark uses hold-out PRs whose later commits are checked to be real fixes before the review runs.
  • v2 was wrong more often than v1: 3 of 16 findings against 2 of 31. Two PRs are too few to say whether that is real, but v2 does report more by design, since it counts a defect the change makes worse as part of the change.
  • Each review takes 10 to 27 minutes and runs make gate, so run one at a time.
